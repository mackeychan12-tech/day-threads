## 首版 Release 草稿

标题：`v0.1.0 · 今日线程：被打断后，找回刚才那件事`

正文：

```text
方案做到一半，一条消息、一个电话，把你叫去处理别的事。忙完回来，刚才做到哪了？

这是「今日线程 · 项目看板」的首个公开版本。把手头的事放在眼前，被打断时暂停，回来再继续，之前的计时时段也会留下。今天没做完，明天接着做。

离开前还可以双击事项文字，留一句「预算已核，接着检查交期」，给回来继续做的自己留条线索。这句话由你写下，工具保存文字和时段。

还可以切到周甘特图，按月安排项目占用周，写整周注释与项目备注，把已完成项目放进完成分组，或把未完成项目顺延到下个月。

设置中可调整每日休息、每周工作日、节假日和指定日期，以及自动带入、同时计时、回车动作、默认视图和动画。默认延续原流程；历史时段保留当时的休息规则，改设置不会重算过去。

开始使用：
- 先打开 demo.html，体验完全虚构、可重置的演示。
- 实际使用打开 index.html，用桌面版 Chrome 或 Edge 选择程序所在文件夹并允许读写。
- 不用构建、不用账号、不用配置后端，数据写入自己的 看板数据.json。
- 采用 MIT 许可证，完整文本见 LICENSE。

请留意：
- 这是个人工作台。共享文件没有实时合并或并发写入保证，请避免同时编辑。
- 休息默认 12:00–13:00，可关闭或调整为一段同日区间；多件事同时计时会分别累计，不适合作为考勤或精确专注时长。
- 默认每周工作日为周一至周五，启用内置 2025、2026 年中国节假日与调休；可关闭内置安排或指定日期，但内置数据不自动更新。日期设置只影响甘特表头，不控制计时上下班。
- 「导出」只包含今日线程历史；完整备份请复制 看板数据.json。
- 备份导入会替换相应记录，不是合并；普通删除和涂改没有通用撤销。

更完整的说明请查看 README。
```

正式发布时保留仓库中的 MIT `LICENSE`，并在 Release 中提供仓库和演示链接。

## 可直接发布的中文介绍

标题：**消息回完、电话挂断，刚才做到哪了？**

正文：

> 方案改到一半，同事发来一条消息。回完消息，又去处理了一个临时问题。
>
> 等重新坐回来，盯着屏幕想了想：刚才做到哪了？下一步准备做什么来着？
>
> 我做了一个自己用的工作看板，叫「今日线程」，想给这些被打断的工作留条线索。
>
> 手头的事放在正在做的区域，被打断时暂停，回来再继续，之前做过的时段也会留下。离开前可以双击事项文字，留一句「预算已核，接着检查交期」。回来看到这句话，就知道下一步做什么。
>
> 今天没做完，明天还可以接着做。昨天的未完成事项会带到今天，计时先停着，等准备好了再继续。过去哪天做了什么可以回看，也能复制日报。
>
> 另一个页签是周甘特图：按月安排项目占用哪些周，写本周提醒和项目备注，还能看到中国节假日、调休补班。两个视图各自记录，不做自动关联。
>
> 原来固定的午休和工作日，现在可以在设置里调整。默认仍扣除 12:00–13:00；也可关闭休息扣除、选择每周工作日、单独设某天上班或休息。跨天带入、同时计时和回车动作也能选。之前的计时保留原规则，改设置不会把过去重算一遍。
>
> 程序就是一个 HTML 文件，不用账号，不用搭后端。实际数据写在自己选择的文件夹中；完整备份就是复制那份 JSON 数据文件。
>
> 我准备了一套完全虚构的演示，里面特意放了被打断后接着做、昨日带来、跨午休和待做/完成混合状态。打开 demo.html 就能试，事项和设置在刷新或重置后都会复原，不会碰实际工作数据。
>
> 它适合个人使用。没有实时多人协作，计时也不是考勤：几件事同时运行会分别累计。节假日目前内置 2025、2026 年，需要继续维护。
>
> 仓库说明里写了使用方式、数据边界和贡献方法。如果你也有类似的工作习惯，欢迎看看它是否适合你。
