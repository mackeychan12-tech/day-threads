# 演示脚本

目标：让第一次看到的人理解「事情被打断后还能接着做」，再看到周甘特图的月度安排。重点是实际工作过程，不是做满一屏漂亮的完成项。

## 演示环境

打开仓库中的 `demo.html`，用桌面版 Chrome 或 Edge，建议窗口宽度至少 1280 像素。所有事项与项目都是虚构的，不连接实际数据文件。

演示时钟从 2026 年 10 月 19 日 14:35 起继续走时；刷新或点击重置会恢复初始事项和设置。演示设置只保存在当前页面内。开始录屏前重置一次，避免前次操作改变初始画面。截图使用 `docs/images/today.png` 与 `docs/images/gantt.png`。

## 60–90 秒录屏

| 时间 | 操作与画面 | 建议旁白 |
|---|---|---|
| 0–10 秒 | 停留今日线程，让正在做、待做、完成同时出现 | 「一天里的工作，经常做到一半就被打断。我想记住现在在做什么，也记住刚才停在哪里。」 |
| 10–25 秒 | 指向有多段时段条的事项，暂停后再继续；指向昨日带来的暂停事项 | 「同一件事可以做几段。昨天没做完的会带到今天，先暂停，想接着做时再继续。」 |
| 25–40 秒 | 把一条待做拖到正在做，再标记完成；从完成区撤销一次完成 | 「想到的先记下来，开始做再计时。拖到哪个区，就变成什么状态。」 |
| 40–50 秒 | 日历看前一天，再回今天；点击复制日报，粘贴到临时空白文本中 | 「以前哪天做了什么，可以回看；日报直接复制完成和进行中的事项。」 |
| 50–70 秒 | 切到周甘特图，指向 10 月的节假日和补班，给一个项目拖涂周安排，再打开备注 | 「项目按月看，安排在哪几周一眼能扫到。整周提醒和项目备注分开写，中国节假日和调休也能看到。」 |
| 70–85 秒 | 展示完成分组和顺延下月入口，最后停在整体画面 | 「实际使用时，数据放在自己选的文件夹里。一个 HTML 文件，不用账号，也不用搭后端。」 |

录屏不必演完所有能力。若控制在 60 秒，省略日报粘贴和顺延下月的实际执行。停顿处让用户看清状态变化，避免快速连续拖动。

## 虚构数据为什么这样安排

| 混合状态 | 要表达的重点 |
|---|---|
| 正在做的事项含多个工作时段 | 中断是日常的一部分，暂停后可以继续，时段条保留过程 |
| 多件事同时计时 | 支持并行推进，不强制单任务；总投入不是独占专注时间 |
| 昨日带来且已暂停 | 默认开启的跨天接续保留累计投入，不自动继续计时 |
| 做过又放回待做、从未开始的待做 | 待做不等于全部从零开始 |
| 跨午休的已完成事项 | 默认 12:00–13:00 休息时，11:40–13:20 的投入为 40 分钟，而不是 100 分钟 |
| 无计时直接完成 | 快速事项也能记下，不必为了完成而先开计时 |
| 今日完成与尚未完成并存 | 日报和完成统计反映真实的混合进展 |
| 甘特连续周、间隔周、单周和空安排 | 展示周粒度安排，而不是所有项目统一铺满整月 |
| 整周注释与项目周备注 | 分清本周共同提醒和某个项目的进展、风险 |
| 10 月假期、10 月 10 日补班、已完成项目 | 突出中国工作日显示及完成分组 |

## 需要准确说明的地方

- 两个视图各自记录，同名文字不表示自动关联。
- 实际页使用 `看板数据.json`；演示页不读写该文件，交互不长期保存。
- 休息默认 12:00–13:00，可关闭或调整为一段同日区间，开始须早于结束，不支持跨午夜。并行任务分别累计，不能把总和说成专注时长。
- 休息设置只影响后续时段；正在计时的事项在修改时分段后继续。已记录时段按当时规则计算，旧时段缺少规则时仍按原 12:00–13:00，演示中已完成的 40 分不会随新设置改变。
- 默认每周工作日为周一至周五，启用内置 2025、2026 年中国节假日与补班；可关闭内置安排、调整每周工作日或指定日期。指定日期优先，其次是启用的内置安排，最后是每周工作日；日期设置只影响甘特表头，不控制计时上下班。
- 未录入年份会提示，按已设每周工作日显示；内置节假日不会自动更新。
- 项目顺延下月只带名称和颜色，下月的周安排为空；同名项目不会重复创建。
- 支持撤销完成，不支持所有操作的通用撤销或历史版本回滚。
- 文件冲突是让用户选择数据并下载另一份备份，不是实时多人协作或自动合并。

## 可选：补一段设置演示

主录屏仍围绕中断后继续。若观众问到个人习惯，可补录设置：展示每日休息、每周工作日、指定日期，再指向自动带入、同时计时、回车动作、默认视图与动画选项。说明默认值延续原流程，规则可按习惯选择；主题只属于当前浏览器，其余设置随完整数据保存。

如需实际改变休息并验证，不要用已完成的 40 分钟样例证明新规则生效；它保留旧时段规则。应新建一个演示事项，先运行，再调整休息，展示调整前后的分段。演示里的改动刷新就会复原，不会更改正式页设置。历史只读、连接授权和冲突处理等保护规则仍保留。

## 可选：单独录一段数据文件说明

只有正式使用页支持真实文件夹连接；需要额外展示时，将 `index.html` 放进单独的测试文件夹，用虚构数据连接。不要选择日常工作目录。

按「授权文件夹 → 新建事项 → 等待保存 → 刷新仍存在」展示即可。需要展示冲突时，用两个浏览器打开该测试副本，分别修改，再展示冲突选择与备份下载。冲突演示应先验证流程，不承诺同时写入始终安全。
